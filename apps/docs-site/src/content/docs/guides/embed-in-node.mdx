<p class="doc-lede">Add AskDB to a TypeScript service. It generates checked SQL from a question and hands it back. Your service runs it through its own database connection, read-only.</p>

## Wire it into a handler

A handler has two parts. The first gets SQL for a question from AskDB, and the second runs that SQL against your database. How you give AskDB a model changes the first part. Your database engine changes the second part, and with `ask()` it also sets the `dialect` you pass in the first.

You can give AskDB a model in two ways, and both are first-party and return the same result:

- **AskDB builds the model:** `createAskDb()` from `@askdb/client` reads the model, schema and dialect from `askdb.config.ts`, the file that `askdb init` wrote and that the CLI and Studio read.
- **Your app builds the model:** `ask()` from `@askdb/core` takes a Vercel AI SDK model that your app builds, and reads no config.

If your app already builds AI SDK models, building this one yourself keeps all model configuration in one place. If it doesn't, `askdb.config.ts` already holds it. [Bring your own model](/guides/bring-your-own-model/#which-should-i-use) compares the two.

### 2. Get SQL for a question

Create `generate-sql.ts`. It sets up AskDB once at startup and exports `generateSql(question)`, which returns checked SQL:

<Tabs syncKey="wiring">
  <TabItem label="AskDB builds the model">

```ts
// generate-sql.ts
import { createAskDb } from "@askdb/client";
import { bootstrapAskDbEnv, getAskDbRuntimeConfig } from "@askdb/config";

// Loads .env and askdb.config.ts from the working directory.
bootstrapAskDbEnv({ cwd: process.cwd() });

const askdb = createAskDb({
  config: getAskDbRuntimeConfig(),                 // ai.provider picks the model
  schema: { path: "./askdb" },                     // or set host.schemaPath in config and omit
});

export function generateSql(question: string) {
  return askdb.ask(question);
}
```

The dialect follows the engine the schema artifact recorded at introspection, so a SQLite schema gets SQLite SQL with no change. Set `dialect` in `askdb.config.ts` to override it. The schema loads on the first `ask()` and stays in memory on the client. If the artifact changes while the process runs, call `askdb.reload()`.

On `askdb.ask(question, overrides)`, the question is the first argument and the other options are per-call overrides. Pass `schema` per call to serve several schemas from one client. `schema`, `model` and `dialect` take the client's forms, and `mode` and `omitSensitiveIdentifiersFromNlToSqlPrompt` can only tighten what the config sets. See [`AskOverrides`](/reference/client-api/#overrides--askoverrides).

  </TabItem>
  <TabItem label="Your app builds the model">

```ts
// generate-sql.ts
import { ask, loadSchema } from "@askdb/core";
import { openai } from "@ai-sdk/openai";

// loadSchema is synchronous; it autodetects the artifact directory,
// a bundled .bundle.json, or a bare schema.json. Load once at startup.
const schema = loadSchema("./askdb");
const model = openai("gpt-4o-mini");               // reads OPENAI_API_KEY

export function generateSql(question: string) {
  return ask({
    question,
    schema,
    dialect: "postgres",                           // the engine the schema came from: "sqlite" for a SQLite file
    model,
  });
}
```

Set `dialect` to the engine you introspected: `"postgres"`, `"cockroachdb"`, `"mysql"`, `"mariadb"`, `"sqlite"` or `"sqlserver"`. Every option `ask()` takes, such as modes, tenant scope, retrieval and sensitive-field handling, is in the [@askdb/core API reference](/reference/core-api/).

  </TabItem>
</Tabs>

`./askdb` is the folder `askdb introspect` writes the schema artifact to, unless `introspection.outputDir` in `askdb.config.ts` names another one.

### 3. Run the SQL in a handler

Create `ask-handler.ts`. It calls `generateSql()`, logs the SQL and runs it read-only. It's the same for both ways of building the model:

<Tabs syncKey="engine">
  <TabItem label="PostgreSQL">

```ts
// ask-handler.ts
import { Pool } from "pg";
import { generateSql } from "./generate-sql.js";

// Connect as a read-only, least-privilege role, with a statement timeout.
const pool = new Pool({
  connectionString: process.env.DATABASE_URL,
  statement_timeout: 5000,
  max: 10,
});
// An idle client whose connection drops emits on the pool; without a listener, the process exits.
pool.on("error", (err) => console.error({ err }, "idle database client error"));

// Runs one generated statement in a read-only transaction.
async function runReadOnly(sql: string, params: unknown[] = []) {
  const client = await pool.connect();
  // A dropped connection then fails the query instead of crashing the process.
  const onError = () => undefined;
  client.on("error", onError);
  try {
    await client.query("BEGIN READ ONLY");
    // queryMode "extended" sends the statement on its own, so a stacked second statement fails.
    // A variable, not an inline object: @types/pg doesn't declare queryMode.
    const query = { text: sql, values: params, queryMode: "extended" };
    const { rows } = await client.query(query);
    return rows;
  } finally {
    await client.query("ROLLBACK").catch(() => undefined);
    client.off("error", onError);
    client.release();
  }
}

export async function askQuestion(question: string) {
  const { sql, tenantParams } = await generateSql(question);

  // Audit hook — log every question and generated SQL.
  console.log({ question, sql });

  // `sql` runs with `tenantParams`, which is empty unless you pass a tenant scope.
  const rows = await runReadOnly(sql, tenantParams ?? []);
  return { sql, rows };
}
```

  </TabItem>
  <TabItem label="MySQL">

```ts
// ask-handler.ts
import mysql from "mysql2/promise";
import { generateSql } from "./generate-sql.js";

// Connect as a read-only, least-privilege user.
const pool = mysql.createPool({ uri: process.env.DATABASE_URL, connectionLimit: 10 });

// Runs one generated statement in a read-only transaction, with a 5 s statement timeout.
// mysql2's types don't take unknown[], so params is any[].
async function runReadOnly(sql: string, params: any[] = []) {
  const conn = await pool.getConnection();
  try {
    // MySQL reads max_execution_time in ms. On MariaDB, use SET SESSION max_statement_time = 5 (seconds).
    await conn.query("SET SESSION max_execution_time = 5000");
    await conn.query("START TRANSACTION READ ONLY");
    // execute() prepares the statement, so a stacked second statement fails.
    const [rows] = await conn.execute(sql, params);
    return rows;
  } finally {
    await conn.query("ROLLBACK").catch(() => undefined);
    conn.release();
  }
}

export async function askQuestion(question: string) {
  const { sql, tenantParams } = await generateSql(question);

  // Audit hook — log every question and generated SQL.
  console.log({ question, sql });

  // `sql` runs with `tenantParams`, which is empty unless you pass a tenant scope.
  const rows = await runReadOnly(sql, tenantParams ?? []);
  return { sql, rows };
}
```

On the `ask()` path, set `dialect: "mysql"` in `generate-sql.ts`, or `"mariadb"` for MariaDB. On MariaDB, also swap the timeout line for `max_statement_time`, as its comment says.

  </TabItem>
  <TabItem label="SQLite">

```ts
// ask-handler.ts
import Database from "better-sqlite3";
import { generateSql } from "./generate-sql.js";

// Open the file read-only, so a generated write fails.
const db = new Database("./shop.db", { readonly: true, fileMustExist: true });

// Runs one generated statement. prepare() takes one statement, so a stacked second statement fails.
function runReadOnly(sql: string, params: unknown[] = []) {
  return db.prepare(sql).all(...params);
}

export async function askQuestion(question: string) {
  const { sql, tenantParams } = await generateSql(question);

  // Audit hook — log every question and generated SQL.
  console.log({ question, sql });

  // `sql` runs with `tenantParams`, which is empty unless you pass a tenant scope.
  const rows = runReadOnly(sql, tenantParams ?? []);
  return { sql, rows };
}
```

`./shop.db` is the Quickstart's database; change it to your own file. On the `ask()` path, set `dialect: "sqlite"` in `generate-sql.ts`.

SQLite has no statement timeout, and `better-sqlite3` runs each query synchronously. A slow generated query therefore blocks the whole Node process until it finishes, and every other request waits. Use this handler for local or single-user work, and use a database server with a statement timeout for a shared service.

  </TabItem>
  <TabItem label="SQL Server">

```ts
// ask-handler.ts
import mssql from "mssql";
import { generateSql } from "./generate-sql.js";

// Connect as a read-only, least-privilege login, with a 5 s request timeout.
// mssql reads an ADO.NET string or a config object, not an mssql:// URL.
const pool = await mssql.connect({
  server: process.env.DB_HOST ?? "localhost",
  database: process.env.DB_NAME,
  user: process.env.DB_USER,
  password: process.env.DB_PASSWORD,
  requestTimeout: 5000,
  pool: { max: 10 },
});

// Runs one generated statement. AskDB's sqlserver dialect writes parameters as @p0, @p1, …
async function runReadOnly(sql: string, params: unknown[] = []) {
  const request = pool.request();
  params.forEach((value, index) => request.input(`p${index}`, value));
  const { recordset } = await request.query(sql);
  return recordset;
}

export async function askQuestion(question: string) {
  const { sql, tenantParams } = await generateSql(question);

  // Audit hook — log every question and generated SQL.
  console.log({ question, sql });

  // `sql` runs with `tenantParams`, which is empty unless you pass a tenant scope.
  const rows = await runReadOnly(sql, tenantParams ?? []);
  return { sql, rows };
}
```

On the `ask()` path, set `dialect: "sqlserver"` in `generate-sql.ts`. A server with a self-signed certificate also needs `options: { trustServerCertificate: true }`, in development only: see [Connect to SQL Server](/guides/connect-to-sql-server/#4-connect-your-own-pool).

SQL Server has no read-only transaction, and `mssql` runs a whole batch. So the login's grants are what stop a write that AskDB's checks miss: give it `SELECT` and nothing else ([Database role](/guides/run-safely-in-prod/#database-role)).

  </TabItem>
</Tabs>

### 4. Try it

Call the handler from a short script:

```ts
// try-it.ts
import { askQuestion } from "./ask-handler.js";

askQuestion("How much has each customer spent in total, highest first?").then(({ rows }) => console.table(rows));
```

Run it with [tsx](https://tsx.is/), which runs TypeScript files directly. `--env-file` loads your API key from `.env`, and your connection variables for PostgreSQL, MySQL or SQL Server:

```bash
npx tsx --env-file=.env try-it.ts
```

It logs the question and the SQL, then prints the rows as a table. If it fails with `no AI API key configured` or `Incorrect API key provided`, check that `.env` has your provider's key.

## Run the SQL it returns

AskDB returns checked SQL; your handler logs it, runs it, and returns the result. `runReadOnly` reads every row the query returns. To cap the rows, use `runCapped` from [Cap the rows a query returns](/guides/cap-the-rows-a-query-returns/), as the [Express example](#complete-example-express-server) below does.

`askdb.ask()` and `ask()` both return the query in two forms, each with its own array. Run `sql` with `tenantParams`, the tenant IDs for its markers, which it has only when you pass a tenant scope. Or run `unboundSql` with `params`, which binds every value as a parameter. Never mix the two arrays. `unboundSql` comes with `parameterize` on, the default; set `parameterize: false` to save the output tokens it costs. The result also has `verdict`, what AskDB's SQL checks found, and `usage`, the token counts when your provider reports them. [Result — `AskPipelineResult`](/reference/core-api/ask/#result--askpipelineresult) lists every field.

<Aside type="note">
These examples use `pg`, `mysql2`, `better-sqlite3` and `mssql` to run the SQL, but the driver is your choice — AskDB never opens a connection. If you already use an ORM or query builder (Prisma, Drizzle, Sequelize, Knex, …), skip the driver and pass the returned `sql` string and its values (`tenantParams ?? []`) to your existing client, e.g. `prisma.$queryRawUnsafe(sql, ...values)` or `db.execute(sql, values)`.
</Aside>

To run the same query again with a new value, such as another month, without a model call, see [Rerun a query with new values](/guides/rerun-a-query-with-new-values/).

<Aside type="caution">
AskDB's SQL checks catch common model mistakes but aren't a security boundary. Connect as a read-only, least-privilege role and keep a statement timeout set. On SQLite, opening the file read-only stops writes, but nothing stops a slow query. See [Run generated SQL safely](/concepts/safety-boundaries/#run-generated-sql-safely).
</Aside>

## Switching engines

With `createAskDb()`, the dialect follows the engine the schema artifact recorded at introspection, unless `askdb.config.ts` sets `dialect`. With `ask()`, change `dialect` to `"postgres"`, `"cockroachdb"`, `"mysql"`, `"mariadb"`, `"sqlite"` or `"sqlserver"`. For the full migration matrix, see [Switch engines](/guides/switch-engines/).

## Complete example: Express server

The snippet below is a copy-paste-ready Express server. Schema, model, and dialect are fully config-driven — `askdb.config.ts` sets `host.schemaPath` and the AI provider; `server.ts` only handles HTTP.

The `/ask` endpoint accepts an optional `execute` flag: `false` (default) returns just the SQL; `true` also runs it and returns the rows. It runs the SQL the way [Run safely in production](/guides/run-safely-in-prod/) describes: under a read-only role with a statement timeout, inside a read-only transaction, and capped at 1,000 rows ([Cap the rows a query returns](/guides/cap-the-rows-a-query-returns/)). Errors go to the server log under a correlation ID; the caller gets that ID and a generic message, because an error can carry provider or schema details.

The server runs its SQL on PostgreSQL, like the runnable example it mirrors. For another engine, replace `pg` and `runCapped` with that engine's helper from [Cap the rows a query returns](/guides/cap-the-rows-a-query-returns/). The helper opens its own connection, so also give that connection a statement timeout, as your engine's handler in step 3 does.

```ts
// server.ts
import { randomUUID } from "node:crypto";
import { createAskDb } from "@askdb/client";
import { bootstrapAskDbEnv, getAskDbRuntimeConfig } from "@askdb/config";
import express, { type Request, type Response } from "express";
import pg from "pg";

bootstrapAskDbEnv({ cwd: process.cwd() });

const app = express();
app.use(express.json());

const askdb = createAskDb({
  config: getAskDbRuntimeConfig(),
  // schema resolved from host.schemaPath in askdb.config.ts
});

// Connect as a read-only, least-privilege role, with a statement timeout.
const pool = process.env.DATABASE_URL
  ? new pg.Pool({ connectionString: process.env.DATABASE_URL, statement_timeout: 5000 })
  : null;
// An idle client whose connection drops emits on the pool; without a listener, the process exits.
pool?.on("error", (err) => console.error({ err }, "idle database client error"));

const ROW_CAP = 1000;

// Runs one generated statement in a read-only transaction and reads at most
// ROW_CAP rows, as in the docs' "Cap the rows a query returns" guide.
async function runCapped(db: pg.Pool, sql: string, params: unknown[] = []) {
  const client = await db.connect();
  const onError = () => undefined;
  client.on("error", onError);
  try {
    await client.query("BEGIN READ ONLY");
    // A variable, not an inline object: @types/pg doesn't declare queryMode.
    const declare = { text: `DECLARE askdb_rows NO SCROLL CURSOR FOR ${sql}`, values: params, queryMode: "extended" };
    await client.query(declare);
    const { rows } = await client.query(`FETCH ${ROW_CAP + 1} FROM askdb_rows`);
    return { rows: rows.slice(0, ROW_CAP), truncated: rows.length > ROW_CAP };
  } finally {
    await client.query("ROLLBACK").catch(() => undefined);
    client.off("error", onError);
    client.release();
  }
}

app.post("/ask", async (req: Request, res: Response) => {
  const correlationId = randomUUID();
  const { question, execute } = (req.body ?? {}) as { question?: unknown; execute?: unknown };

  if (typeof question !== "string" || question.trim() === "") {
    res.status(400).json({ correlationId, error: "question is required and must be a non-empty string" });
    return;
  }

  if (execute !== undefined && typeof execute !== "boolean") {
    res.status(400).json({ correlationId, error: "execute must be a boolean when provided" });
    return;
  }

  if (execute && !pool) {
    res.status(500).json({ correlationId, error: "DATABASE_URL is not configured" });
    return;
  }

  // Errors can carry provider or schema details: log them, and send the caller a generic message.
  let result;
  try {
    result = await askdb.ask(question.trim());
  } catch (err) {
    console.error({ correlationId, question, err });
    res.status(500).json({ correlationId, error: "Could not generate SQL for this question. See the server log for this correlationId." });
    return;
  }

  // `sql` runs with `tenantParams` (none here: this server passes no tenant scope).
  const { sql, tenantParams } = result;
  console.log({ correlationId, question, sql, execute: execute === true });

  if (!execute) {
    res.json({ correlationId, sql });
    return;
  }

  try {
    const { rows, truncated } = await runCapped(pool!, sql, tenantParams ?? []);
    res.json({ correlationId, sql, rows, truncated });
  } catch (err) {
    console.error({ correlationId, sql, err });
    res.status(500).json({ correlationId, sql, error: "The query failed. See the server log for this correlationId." });
  }
});

app.get("/health", (_req: Request, res: Response) => {
  res.json({ status: "ok" });
});

app.listen(3000, () => console.log("listening on http://localhost:3000"));
```

import { defineConfig, env, type AskDbConfig } from "@askdb/config";

    provider: "openai",
    providerConfig: { openai: { apiKey: env("OPENAI_API_KEY") } },
